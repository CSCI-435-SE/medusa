Coding Conventions:
Formatting (Prettier): no semicolons, double quotes, 2 space indentation, ES5 trailing commas, always use parentheses in arrow functions
Naming convention: 
Files: kebab-case (define-config.ts)
Types/Interfaces/Classes: PascalCase
Functions/Variables: camelCase
Constants: SCREAMING_SNAKE_CASE
DB fields: snake_case

Branching and Commit Conventions:
All changes should be part of a branch and submitted as a pull request - your branches should be prefixed with one of: fix/ for bug fixes, feat/ for features, or docs/ for documentation changes.

# One-time setup: clone the team repo (skip if already done)
git clone https://github.com/CSCI-435-SE/medusa.git
cd medusa

# Before starting each issue: make sure you are on a fresh main
git checkout main
git pull origin main

# Create a branch named for the issue
git checkout -b feat/issue-17-dark-mode      # new feature
git checkout -b fix/issue-42-toast-dismiss   # bug fix

# ... make your changes, run tests ...

# Stage and commit
git add <the files you changed>
git commit -m "feat: add dark mode toggle (#17)"

# Push the branch to the team repo
git push origin feat/issue-17-dark-mode

Prefix							Use for:
feat/issue-<N>-short-description		new features
fix/issue-<N>-short-description		bug fixes
chore/short-description				docs, config, dependency 
updates

Pull Request Conventions:
Branch-based workflow, PR into main. Keep commits small. All PRs should include tests for the changes that are included and should be reviewed by at least one other team member.

Testing Expectations:
All PRs should include tests for the changes that are included. If all changes are not tested, then the PR should not be approved.

AI Tool Use:
We will be using Claude/Claude Code. Claude.md gives a full overview of coding conventions that should be followed by ourselves and the ai tools. Everything generated by an ai agent or chatbot should be fully examined and understood before including it in a PR. AI chats are stored in ai-logs/sprint0/<your-github-username>/ in the team repo.

Definition of Done:
Definition of done is when all requirements are met and there are sufficient tests for the issue/feature covered. Tests that were previously passing should continue to pass. Proper documentation is provided if needed. Code and tests are reviewed by at least one teammate.
